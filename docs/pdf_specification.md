# Pure ActionScript Binary PDF 1.7 Specification

The `stencil.format.PDFDocument` class implements a complete, zero-dependency binary PDF 1.7 generator written in pure ActionScript 3. It serializes scene graphs directly into conforming Adobe PDF documents capable of rendering in Adobe Acrobat, PDF.js, Preview, and Ghostscript.

## 1. File Structure Layout

A conforming PDF file generated by Stencil follows the 4-section standard:

```
+-------------------------------------------------------+
| Header: %PDF-1.7                                      |
| Binary Header: %âãÏÓ (High-byte binary marker)        |
+-------------------------------------------------------+
| Body: Indirect Object Dictionaries (1 0 obj ... endobj) |
|   - 1 0: Document Catalog Dictionary                  |
|   - 2 0: Page Tree Root (/Pages)                      |
|   - 3 0: Page Object (/Page)                          |
|   - 4 0: Resource Dictionary (/Resources)             |
|   - 5 0: Content Stream (/Length ... stream)          |
|   - 6 0+: Embedded TrueType/Type 1 Font Descriptors   |
+-------------------------------------------------------+
| Cross-Reference Table (xref)                          |
|   - 10-digit byte offsets for every indirect object   |
+-------------------------------------------------------+
| Trailer Dictionary & Startxref Pointer                |
|   - /Size, /Root reference, byte offset, %%EOF        |
+-------------------------------------------------------+
```

## 2. Graphics State and Vector Stream Operators

Vector shapes from the Stencil scene graph are translated into low-level PostScript/PDF stream operators within the page content stream:

### Coordinate System & State Scoping
- `q`: Push graphics state stack (saves current transformation matrix, clipping path, stroke width, and blend mode).
- `Q`: Pop graphics state stack (restores prior state, preventing leakage between nodes).
- `a b c d e f cm`: Concatenate 2D affine transform matrix $\begin{bmatrix} a & b & 0 \\ c & d & 0 \\ e & f & 1 \end{bmatrix}$ to the current transformation matrix. Note that PDF uses a bottom-left origin ($y$ increases upward); Stencil automatically injects an inversion matrix $y' = H - y$.

### Vector Path Construction
- `x y m`: `moveto` operator establishing the current subpath origin.
- `x y l`: `lineto` operator appending a straight line segment.
- `x1 y1 x2 y2 x3 y3 c`: `curveto` operator appending a cubic Bezier segment with control points $(x_1, y_1), (x_2, y_2)$ and endpoint $(x_3, y_3)$. Quadratic Bezier curves are mathematically elevated to cubic curves via:
  
  $$CP_1 = P_0 + \frac{2}{3}(P_1 - P_0)$$
  $$CP_2 = P_2 + \frac{2}{3}(P_1 - P_2)$$

- `x y w h re`: Fast rectangle path primitive.
- `h`: `closepath` operator closing the active contour with a straight segment to the initial `moveto`.

### Path Painting & Shading
- `r g b rg`: Set non-stroking (fill) color in DeviceRGB space ($r, g, b \in [0, 1]$).
- `r g b RG`: Set stroking color in DeviceRGB space.
- `w w`: Set stroke line width in user space units.
- `f`: Fill the path using the non-zero winding number rule.
- `f*`: Fill the path using the even-odd winding rule.
- `S`: Stroke the path with the active line width and dash pattern.
- `B`: Fill and stroke the path in a single pass.
- `W n`: Set the active clipping path using non-zero winding.

## 3. Cross-Reference Table (XRef) & Trailer Generation

Byte-exact indexing is essential for random-access PDF parsers. Stencil tracks the precise byte offset of each indirect object during compilation into a continuous byte array:

```
xref
0 6
0000000000 65535 f 
0000000015 00000 n 
0000000068 00000 n 
0000000142 00000 n 
0000000284 00000 n 
0000000412 00000 n 
trailer
<< /Size 6 /Root 1 0 R >>
startxref
589
%%EOF
```

Each xref entry is formatted as exactly 20 characters (`%010d 00000 n \n`), guaranteeing cross-platform byte alignment across Windows, macOS, and Linux runtimes.
